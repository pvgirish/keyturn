KeyTurn makes “done” a result you can check.

For engineers carrying out a planned database password change with IBM Bob. KeyTurn checks that customers work with the new credential, the old one is refused, and reconnects and queued jobs still succeed — and keeps a handover record.

Why editing the files is not enough

Apps read .env.production when they start. Running apps keep the old password until they are recreated.
Connection pool (PgBouncer) has its own config and auth file, and keeps open sessions that logged in with the old password.
Database stores the role's password. Until it changes, the old password still works — and nothing looks broken.

In our lab, under a short request, plain IBM Bob edited every copy of the password in the files and listed the live steps as next steps — three times out of three the old password still worked. With the outcome spelled out, plain Bob succeeded. The gap is the definition of “done”; KeyTurn makes it a reusable check.

How it works inside IBM Bob

Three custom modes
KeyTurn Inventory (read-only: every copy and who reads it) → KeyTurn Plan (ordered handover, either method) → KeyTurn Execute (checks after every step).
A skill
credential-handover: what “complete” means, both valid methods (same user, new user), and never printing a secret.
A gate hook (PreToolUse)
Refuses covered unsafe steps with the reason, e.g. restarting the apps onto a password the database would reject.
A done-check hook (Stop)
Records VERIFIED, FAILED or UNVERIFIED next to the work. It records; Bob's Stop hook cannot block “done”.
A 12-tool MCP checker, no AI
Login tests, running config, sessions, customer probes, a transition watch, restart / reconnect / migration / delayed-job tests, the three proofs, the record.
The three proofs
1 customers on the new credential · 2 old credential refused, no old sessions · 3 recreate, reconnect, restart, migration and a queued job all pass. VERIFIED only on the current state.

Run it yourself

git clone https://github.com/pvgirish/keyturn && cd keyturn/lab/harness
./setup_stack.sh && ./before_p2a.sh        # Docker; builds the lab in ~/mastodon-ops
./install_keyturn.sh                       # installs KeyTurn into that Bob workspace
python3 -m unittest discover -s ../../keyturn/tests   # 81 tests, Python 3.9+ standard library

Open ~/mastodon-ops in IBM Bob, check Settings → Modes, Skills, Hooks and MCP, and ask Bob to rotate the database password. Synthetic lab data only.

Limits

  • One deployment shape today: apps → PgBouncer (auth_file) → Postgres, in Docker.
  • Covered commands only: script files, Python/Ruby file writes, podman and interactive psql are not gated (the proofs still judge the end state).
  • Customer checks are sampled about every 5 s. No zero-downtime promise.
  • Bob's Stop hook cannot block “done”; KeyTurn records a verdict instead.
