## Why v0.2.1
This release answers the end-to-end review of 27 Sep (`evidence/v02-end-to-end-review-2026-09-27/`).

**Stale VERIFIED after an outage (High) — fixed.**
- Every proofs run now records which containers were running: the apps, PgBouncer and Postgres, each with status, container id and start time.
- The done-check compares them with the live state. A stop, restart or recreate after the proofs gives UNVERIFIED until the proofs run again.
- A change during the proofs themselves is an observation error.
- Checked live: sidekiq stopped → UNVERIFIED ("sidekiq is exited now"); started again → UNVERIFIED ("sidekiq was restarted"); proofs rerun → VERIFIED.
- The reviewer's `reproduce_stale_verified.py` now returns UNVERIFIED.

**Missing or untestable pooler login (High) — fixed, fails closed.**
- A reload or restart is refused unless Postgres positively accepts *both* the app credential and PgBouncer's backend login.
- A missing database entry, or an entry without a user/password, is refused.
- auth_file or auth_query passthrough is not a supported route. It would need its own positive check.
- The reviewer's `reproduce_missing_mapping.py` now returns `activate.ok = false`.

**Watch run boundaries (Medium) — fixed.**
- Each `watch start` creates a run ID and takes one synchronous first sample.
- A failing first sample blocks the change ("customers were already failing").
- The summary covers only the current run and lists earlier runs separately.
- Failures inside KeyTurn's own restart tests are counted apart from the change.
- Gaps longer than 15 s are listed as unobserved.
- A watch that ends without being stopped reports DIED.
- Run IDs are unique even within one second.

**Also changed:**
- `docker stop`, `docker compose stop`, `down` and `rm` of the apps or PgBouncer are now gated. The next start of a stopped service reads the credentials in the files.
- The handover record now opens with the current done-check result. It states who made the changes (as given by the caller), and says "no inventory was supplied" when there is none. It says whether gaps were stated, and lists KeyTurn's known limits and the code digest.
- The demo script now shows a hook error as an error, never as "allowed", and stops if any mutation fails.

## Gate coverage and known gaps
- **Covered** (unit and E2E tests):
  - SQL on the old role in commands, heredocs, `rails runner`, `-f` and `<` SQL files;
  - edits to the hashed file, by the file tools, `sed`, `grep -v`, or `cp`/`mv`/`install`/`cat >`;
  - reload, restart, stop, down, rm and SIGHUP forms for PgBouncer and the apps;
  - edits to `.bob/`;
  - reads of KeyTurn's private folder.
- **Not covered** (not gated; the proofs still judge the end state): script files, Python/Ruby file writes, podman, interactive psql.
- Hook timeouts are in seconds, per IBM's hook documentation. The MCP timeout is treated as milliseconds, based on P2.
